3. STEP 1: LAUNCH PRODUCTION AWS EC2 INSTANCE (CLICK-BY-CLICK CONSOLE SETUP)
================================================================================

Step 1.1: Open EC2 Console
1. Log in to the AWS Management Console: https://console.aws.amazon.com
2. In the top-right corner, confirm the region is `Asia Pacific (Mumbai) ap-south-1`.
3. In the search bar at the top, type "EC2" and click "EC2".
4. In the left navigation panel, click "Instances".
5. Click the orange "Launch instances" button at the top right.

Step 1.2: Name and Tags
- In the "Name" input field, enter: `CloudTwin-Production`

Step 1.3: Application and OS Images (Amazon Machine Image - AMI)
- Under "Quick Start", click the "Ubuntu" box.
- Under "Amazon Machine Image (AMI)", verify the dropdown is set to:
  `Ubuntu Server 22.04 LTS (HVM), SSD Volume Type` (64-bit (x86)).

Step 1.4: Instance Type
- Under "Instance type", click the dropdown and search for:
  `t3.medium` (2 vCPU, 4 GiB Memory).
  *(Why t3.medium: Next.js standalone container production builds require ~2.5 GB RAM.*
  *If using Free Tier `t3.micro`, you must configure a 2GB Linux swapfile as detailed in Step 10).*

Step 1.5: Key Pair (Login Credentials)
- Under "Key pair (login)":
  * If you already have a key pair, select it from the dropdown.
  * If you need to create one:
    1. Click "Create new key pair".
    2. Key pair name: `cloudtwin-key`
    3. Key pair type: `RSA`
    4. Private key file format: Select `.pem` (for OpenSSH / PowerShell / macOS).
    5. Click the orange "Create key pair" button.
    6. Browser will download `cloudtwin-key.pem`. SAVE THIS FILE SAFELY in your 
       Downloads or user folder (e.g. `C:\Users\santa\Downloads\cloudtwin-key.pem`).

Step 1.6: Network Settings
- Click the "Edit" button on the top right of the "Network settings" box.
- Configure each setting:
  1. Virtual private cloud (VPC):
     * Select `cloudtwin-vpc` (or your default VPC).
  2. Subnet:
     * Select a Public Subnet: `cloudtwin-public-subnet-1` (or any public subnet with auto-assign IP).
  3. Auto-assign public IP:
     * Select `Enable` (Very important: allows connecting over SSH and public internet).
  4. Firewall (security groups):
     * Select the radio button: `Create security group`.
     * Security group name: `cloudtwin-ec2-sg`
     * Description: `Allow SSH, HTTP port 80 and HTTPS port 443 ingress for CloudTwin`
  5. Inbound security groups rules:
     * Rule 1 (SSH Access):
       - Type: `SSH` | Protocol: `TCP` | Port range: `22`
       - Source type: `My IP` (Recommended for security) OR `Anywhere-IPv4` (`0.0.0.0/0`)
       - Description: `SSH terminal access`
     * Click "Add security group rule":
     * Rule 2 (HTTP Web Traffic):
       - Type: `HTTP` | Protocol: `TCP` | Port range: `80`
       - Source type: `Anywhere-IPv4` (`0.0.0.0/0`)
       - Description: `Public HTTP web traffic to Nginx`
     * Click "Add security group rule":
     * Rule 3 (HTTPS Web Traffic):
       - Type: `HTTPS` | Protocol: `TCP` | Port range: `443`
       - Source type: `Anywhere-IPv4` (`0.0.0.0/0`)
       - Description: `Secure HTTPS SSL web traffic`

Step 1.7: Configure Storage
- Under "Configure storage":
  * Change size from `8` GiB to: `30` GiB.
  * Volume type: `General purpose SSD (gp3)`.
  * IOPS: `3000` | Throughput: `125` MB/s (Default gp3 settings).
  * Encrypted: `Not encrypted` (or encrypted with default AWS key).

Step 1.8: Review & Launch
- In the right-hand "Summary" panel:
  * Number of instances: `1`
  * Software Image: `Ubuntu Server 22.04 LTS`
  * Instance type: `t3.medium`
  * Storage: `30 GiB gp3`
- Click the orange "Launch instance" button.
- Click "View all instances".
- Wait 60–90 seconds until "Instance state" displays green `Running` and 
  "Status check" displays `2/2 checks passed`.
- Click on `CloudTwin-Production` in the list and copy its **Public IPv4 address**:
  *(Example: `13.232.89.144`)*.

4. STEP 2: CONFIGURE RDS POSTGRESQL SECURITY GROUP FOR EC2
================================================================================

Your EC2 instance needs network permission to communicate with your live Amazon RDS
PostgreSQL database on port 5432. We link the EC2 Security Group directly to the RDS
Security Group:

1. Search "VPC" in the top search bar and open the VPC service.
2. In the left navigation panel, click "Security groups" (under Security).
3. Find and select the RDS security group: `cloudtwin-db-sg` (ID: `sg-084e49d942e94aa18`).
4. Click the "Inbound rules" tab at the bottom -> Click the white "Edit inbound rules" button.
5. Click the "Add rule" button:
   - Type: Select `PostgreSQL` from the dropdown (automatically sets Port `5432`).
   - Protocol: `TCP`.
   - Port range: `5432`.
   - Source type: Select `Custom`.
   - Source: Click inside the search box, start typing `cloudtwin-ec2-sg`, and select 
     the security group you created in Step 1.
   - Description: `Allow CloudTwin EC2 instance access to PostgreSQL`
6. Keep your existing rule for `My IP` intact (allows connecting from your laptop).
7. Click the orange "Save rules" button.

*NOTE: By referencing `cloudtwin-ec2-sg` as the source, EC2 will maintain permanent*
*database connectivity even if its public IP rotates!*


6. STEP 4: AUTOMATED SERVER PROVISIONING (DOCKER, COMPOSE, GIT)
================================================================================

CloudTwin includes an automated server setup script in `infrastructure/deployment/setup-ec2.sh`.
Run these commands in your EC2 terminal window:

Step 4.1: Clone the CloudTwin Repository
```bash
git clone https://github.com/Santa-24/CloudTwin.git
cd CloudTwin
```

Step 4.2: Make the Setup Script Executable & Run It
```bash
chmod +x infrastructure/deployment/setup-ec2.sh
./infrastructure/deployment/setup-ec2.sh
```

Step 4.3: What the Automated Script Installs:
- Performs complete system update (`sudo apt-get update && sudo apt-get upgrade -y`).
- Installs prerequisites (`ca-certificates`, `curl`, `gnupg`, `git`).
- Configures the official Docker APT repository and GPG key.
- Installs `docker-ce`, `docker-ce-cli`, `containerd.io`, and `docker-compose-plugin`.
- Enables systemd Docker service on startup (`systemctl enable docker`).
- Adds the `ubuntu` user to the `docker` security group.

Step 4.4: Verify Docker Installation
Run:
```bash
docker --version
docker compose version
```
Expected output:
`Docker version 27.x.x, build ...`
`Docker Compose version v2.x.x`

7. STEP 5: PRODUCTION ENVIRONMENT VARIABLES (.ENV COPY-PASTE)
================================================================================

Create the production `.env` configuration file in the root of your CloudTwin 
directory on the EC2 instance.

Step 5.1: Open the nano editor:
```bash
nano .env
```

Step 5.2: Copy and paste this exact configuration block:
*(Press Right-Click in PowerShell to paste)*

```ini
# ==============================================================================
# CloudTwin Platform Production Environment Variables (.env)
# Host: AWS EC2 (ap-south-1)
# ==============================================================================

# Core Application Settings
PORT=8000
ENVIRONMENT=production
DEMO_MODE=false

# Live Amazon RDS PostgreSQL Database URL
DATABASE_URL=postgresql://cloudtwin_admin:Santanu2414@cloudtwin-rds-postgres.c5aqg8keklz4.ap-south-1.rds.amazonaws.com:5432/cloudtwin

# Amazon DynamoDB Table (Real-Time Simulation Telemetry Stream)
DYNAMODB_TABLE_SIMULATIONS=CloudTwinSimulationEvents

# Amazon S3 Vaults (Live Architecture Storage & Audit PDF Reports)
AWS_S3_BUCKET=cloudtwin-architecture-vault-santanu-8831
AWS_S3_REPORTS_BUCKET=cloudtwin-reports-vault-santanu-8831

# JWT Secret Key for Session Authentication
JWT_SECRET_KEY=cloudtwin-super-secure-jwt-secret-key-prod-2026

# AWS Region & Programmatic IAM Credentials (Boto3 SDK)
AWS_DEFAULT_REGION=ap-south-1
AWS_REGION=ap-south-1
AWS_ACCESS_KEY_ID=<YOUR_AWS_ACCESS_KEY_ID>
AWS_SECRET_ACCESS_KEY=<YOUR_AWS_SECRET_ACCESS_KEY>
AWS_SESSION_TOKEN=

# AWS Live Mode (false = communicate directly with live AWS APIs)
AWS_MOCK_MODE=false

# AI Recommendation Provider Settings
AI_PROVIDER=gemini
GEMINI_MODEL=gemini-flash-latest
GEMINI_API_KEY=<YOUR_GEMINI_API_KEY>
```

Step 5.3: Save and Exit nano:
1. Press `Ctrl + O` (WriteOut).
2. Press `Enter` (Confirm file name `.env`).
3. Press `Ctrl + X` (Exit editor).

8. STEP 6: BUILD & LAUNCH PRODUCTION CONTAINERS
================================================================================

Now launch the production Docker multi-container stack. This builds:
1. `cloudtwin-backend`: FastAPI running under Uvicorn on internal port 8000.
2. `cloudtwin-frontend`: Next.js production build running on internal port 3000.
3. `cloudtwin-nginx`: Reverse proxy routing public ports 80/443 to frontend & backend.

Step 6.1: Build and Launch Containers in Detached Mode
From your `~/CloudTwin` directory:
```bash
docker compose -f infrastructure/docker/docker-compose.prod.yml up -d --build
```
*(The initial build will take ~3 to 4 minutes to compile the Next.js production bundle)*.

Step 6.2: Verify Container Status
Run:
```bash
docker compose -f infrastructure/docker/docker-compose.prod.yml ps
```
You should see all three containers with status `Up` or `running`:
```

cloudtwin-frontend   cloudtwin-frontend:latest    "node server.js"         frontend   Up (3000/tcp)
```

Step 6.3: Test Local Health from inside EC2

9. STEP 7: ALLOCATE & ASSOCIATE AWS ELASTIC IP (STATIC PUBLIC IP)
================================================================================

Standard EC2 public IPs change if an instance is stopped or restarted. An AWS Elastic IP
provides a permanent, static IPv4 address for your production platform:

Step 7.1: Allocate Elastic IP
1. Open the AWS EC2 Console: https://ap-south-1.console.aws.amazon.com/ec2/home?region=ap-south-1
2. In the left navigation panel, scroll down to "Network & Security" -> click "Elastic IPs".
3. Click the orange "Allocate Elastic IP address" button.
4. Settings:
   - Network Border Group: `ap-south-1`
   - Public IPv4 address pool: `Amazon's pool of IPv4 addresses`
5. Click the orange "Allocate" button at the bottom right.
6. Copy the allocated Elastic IP address (e.g. `13.127.45.101`).

Step 7.2: Associate Elastic IP to CloudTwin Instance
1. In the Elastic IPs list, select the check box next to your new Elastic IP.
2. Click the "Actions" dropdown button at the top right -> select "Associate Elastic IP address".
3. Settings:
   - Resource type: Select `Instance`.
   - Instance: Click inside the search box and select `CloudTwin-Production`.
   - Private IP address: Select the private IP of the instance (auto-filled).
   - Reassociation: Leave unchecked.
4. Click the orange "Associate" button.

Step 7.3: Open CloudTwin in Your Browser
Open your browser and visit:
`http://<YOUR_ELASTIC_IP>`
*(Example: `http://13.127.45.101`)*

THE CLOUDTWIN PLATFORM IS NOW FULLY LIVE ON THE PUBLIC INTERNET!

10. STEP 8: (OPTIONAL) DOMAIN NAME DNS & FREE LET'S ENCRYPT SSL SETUP
================================================================================

If you own a custom domain (e.g., `cloudtwin.io` or `app.yourdomain.com`):

Step 8.1: Point DNS A Record
- Log in to your DNS provider (Route 53, Cloudflare, GoDaddy, Namecheap).
- Create an `A` record:
  * Name: `@` OR `app` (e.g. `app.yourdomain.com`)
  * Type: `A`
  * Value / Target: `<YOUR_ELASTIC_IP>`
  * TTL: `300` (5 minutes)

Step 8.2: Obtain Free Let's Encrypt SSL Certificate
Run in your EC2 SSH session:
```bash
# 1. Stop Nginx temporarily to release port 80
docker compose -f infrastructure/docker/docker-compose.prod.yml stop nginx

# 2. Install Certbot
sudo apt-get update -y
sudo apt-get install -y certbot

# 3. Generate certificate
sudo certbot certonly --standalone -d app.yourdomain.com

# 4. Restart containers
docker compose -f infrastructure/docker/docker-compose.prod.yml start nginx
```

12. STEP 10: PRODUCTION MONITORING, LINUX SWAP & MAINTENANCE COMMANDS
================================================================================

Helpful operational commands to manage your production EC2 server:

--------------------------------------------------------------------------------
A. View Live Logs
--------------------------------------------------------------------------------
- View logs of all services:
  ```bash
  docker compose -f infrastructure/docker/docker-compose.prod.yml logs -f
  ```
- View backend API logs only:
  ```bash
  docker compose -f infrastructure/docker/docker-compose.prod.yml logs -f backend
  ```
- View Nginx web access & error logs:
  ```bash
  docker compose -f infrastructure/docker/docker-compose.prod.yml logs -f nginx
  ```

--------------------------------------------------------------------------------
B. Restart or Stop Services
--------------------------------------------------------------------------------
- Restart all services:
  ```bash
  docker compose -f infrastructure/docker/docker-compose.prod.yml restart
  ```
- Stop all services:
  ```bash
  docker compose -f infrastructure/docker/docker-compose.prod.yml down
  ```

--------------------------------------------------------------------------------
C. Deploying Code Updates (Zero Downtime)
--------------------------------------------------------------------------------
When you push code changes to GitHub, pull and re-deploy on EC2 with:
```bash
cd ~/CloudTwin
git pull origin main
docker compose -f infrastructure/docker/docker-compose.prod.yml up -d --build
```

--------------------------------------------------------------------------------
D. Allocate Linux Swap Memory (Recommended for t3.micro/t3.small)
--------------------------------------------------------------------------------
If building on an instance with under 4 GB RAM, allocate a 2 GB Swap file to 
prevent out-of-memory errors during Docker compilation:
```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

--------------------------------------------------------------------------------
E. Check Disk & Memory Usage
--------------------------------------------------------------------------------
```bash
free -m
df -h
docker system df
```
