2. STEP 0: IAM USER CREATION, POLICIES & PROGRAMMATIC ACCESS KEYS
================================================================================
Your local FastAPI backend uses the Python `boto3` SDK to upload architecture
snapshots to S3, record simulation events into DynamoDB, and query AWS health.
You must create a programmatic IAM User to obtain Access Keys.

1. Search "IAM" in the top search bar and click on "IAM" (Identity and Access Management).
2. In the left navigation panel, click "Users".
3. Click the orange "Create user" button.

Step 0.1: Specify User Details
- User name: `cloudtwin-admin-user`
- Checkbox "Provide user access to the AWS Management Console": LEAVE UNCHECKED 
  (This user is strictly for Python backend API/SDK access).
- Click "Next".

Step 0.2: Set Permissions
- Select the radio button: "Attach policies directly".
- In the search bar under "Permissions policies", search and check the box for each:
  1. `AmazonS3FullAccess`
  2. `AmazonDynamoDBFullAccess`
  3. `AmazonRDSFullAccess`
  4. `CloudWatchReadOnlyAccess`
  (Note: In a development/sandbox account, you may also attach `AdministratorAccess`).
- Click "Next".

Step 0.3: Review & Create
- Review the user name and policies.
- Click the orange "Create user" button at the bottom right.

Step 0.4: Generate & Retrieve Access Keys
- You are redirected to the "Users" list. Click on the newly created user `cloudtwin-admin-user`.
- Click on the "Security credentials" tab (next to Permissions).
- Scroll down to the "Access keys" section and click "Create access key".
- Under "Access key best practices & alternatives", select the radio button:
  "Command Line Interface (CLI)" OR "Application running outside AWS".
- Scroll down and check the confirmation box: "I understand the above recommendation...".
- Click "Next".
- Description tag value (optional): `cloudtwin-backend-key`.
- Click "Create access key".
- COPY THESE TWO VALUES IMMEDIATELY:
  * Access key: `AKIA...` (This will be your `AWS_ACCESS_KEY_ID`)
  * Secret access key: Click "Show" or "Download .csv file" (This will be your `AWS_SECRET_ACCESS_KEY`)
  * NOTE: The secret key will NEVER be shown again after closing this screen.
- Click "Done".

3. STEP 1: AWS VPC & NETWORKING SETUP
================================================================================
CloudTwin models and deploys across a production VPC spanning 2 Availability
Zones with isolated public and private subnets, an Internet Gateway, and a NAT Gateway.

--------------------------------------------------------------------------------
OPTION A: THE ALL-IN-ONE CONSOLE WIZARD ("VPC and more" — RECOMMENDED)
--------------------------------------------------------------------------------
1. In the search bar, type "VPC" and open the VPC service.
2. Click the orange "Create VPC" button.
3. Under "VPC settings", select the radio button "VPC and more".
4. Configure each field:
   - Name tag auto-generation: `cloudtwin`
   - IPv4 CIDR block: `10.0.0.0/16`
   - IPv6 CIDR block: `No IPv6 CIDR block`
   - Tenancy: `Default`
   - Number of Availability Zones (AZs): Select `2`
   - Customize AZs:
     * AZ 1: `ap-south-1a`
     * AZ 2: `ap-south-1b`
   - Number of public subnets: Select `2`
   - Number of private subnets: Select `2`
   - Subnet CIDR block allocation:
     * Public subnet in ap-south-1a: `10.0.0.0/20`
     * Public subnet in ap-south-1b: `10.0.16.0/20`
     * Private subnet in ap-south-1a: `10.0.128.0/20`
     * Private subnet in ap-south-1b: `10.0.144.0/20`
   - NAT gateways ($): Select `In 1 AZ` (Saves AWS cost while routing private subnets to internet)
   - VPC Endpoints: Select `None`
   - DNS options:
     * [x] Enable DNS hostnames (Checked)
     * [x] Enable DNS resolution (Checked)
5. Review the graphical preview on the right.
6. Click the orange "Create VPC" button.
7. Wait 30–60 seconds for VPC, subnets, route tables, IGW, and NAT gateway to deploy.
8. Click "View VPC".

--------------------------------------------------------------------------------
OPTION B: MANUAL SCRATCH CREATION (IF CREATING EACH COMPONENT SEPARATELY)
--------------------------------------------------------------------------------
If you prefer creating each networking piece individually:

1. Create VPC:
   - VPC Console -> "Your VPCs" -> "Create VPC".
   - Select "VPC only" -> Name: `cloudtwin-vpc` -> IPv4 CIDR: `10.0.0.0/16` -> Create.
   - Select `cloudtwin-vpc` -> Actions -> "Edit VPC settings" -> Enable "DNS hostnames" & "DNS resolution" -> Save.

2. Create Subnets (VPC Console -> "Subnets" -> "Create subnet"):
   - Subnet 1 (Public AZ-1):
     * VPC: `cloudtwin-vpc`
     * Subnet name: `cloudtwin-public-subnet-1`
     * Availability Zone: `ap-south-1a`
     * IPv4 subnet CIDR block: `10.0.0.0/20`
     * Click "Add new subnet".
   - Subnet 2 (Public AZ-2):
     * VPC: `cloudtwin-vpc`
     * Subnet name: `cloudtwin-public-subnet-2`
     * Availability Zone: `ap-south-1b`
     * IPv4 subnet CIDR block: `10.0.16.0/20`
     * Click "Add new subnet".
   - Subnet 3 (Private AZ-1):
     * VPC: `cloudtwin-vpc`
     * Subnet name: `cloudtwin-private-subnet-1`
     * Availability Zone: `ap-south-1a`
     * IPv4 subnet CIDR block: `10.0.128.0/20`
     * Click "Add new subnet".
   - Subnet 4 (Private AZ-2):
     * VPC: `cloudtwin-vpc`
     * Subnet name: `cloudtwin-private-subnet-2`
     * Availability Zone: `ap-south-1b`
     * IPv4 subnet CIDR block: `10.0.144.0/20`
   - Click "Create subnet".
   - For both public subnets: Select the subnet -> Actions -> "Edit subnet settings" -> Check "Enable auto-assign public IPv4 address" -> Save.

3. Create Internet Gateway:
   - VPC Console -> "Internet gateways" -> "Create internet gateway".
   - Name: `cloudtwin-igw` -> Click "Create".
   - Select `cloudtwin-igw` -> Actions -> "Attach to VPC" -> Select `cloudtwin-vpc` -> Attach.

4. Create NAT Gateway (For Private Subnets outbound traffic):
   - VPC Console -> "NAT gateways" -> "Create NAT gateway".
   - Name: `cloudtwin-nat-gw`
   - Subnet: Select `cloudtwin-public-subnet-1`
   - Connectivity type: Public
   - Elastic IP: Click "Allocate Elastic IP" -> Click "Create NAT gateway".

5. Create Route Tables:
   - Public Route Table:
     * VPC Console -> "Route tables" -> "Create route table" -> Name: `cloudtwin-public-rt` -> VPC: `cloudtwin-vpc` -> Create.
     * Select `cloudtwin-public-rt` -> "Routes" tab -> "Edit routes" -> "Add route":
       Destination: `0.0.0.0/0` | Target: Internet Gateway (`cloudtwin-igw`) -> Save.
     * "Subnet associations" tab -> "Edit subnet associations" -> Select `cloudtwin-public-subnet-1` and `cloudtwin-public-subnet-2` -> Save.
   - Private Route Table:
     * VPC Console -> "Route tables" -> "Create route table" -> Name: `cloudtwin-private-rt` -> VPC: `cloudtwin-vpc` -> Create.
     * Select `cloudtwin-private-rt` -> "Routes" tab -> "Edit routes" -> "Add route":
       Destination: `0.0.0.0/0` | Target: NAT Gateway (`cloudtwin-nat-gw`) -> Save.
     * "Subnet associations" tab -> "Edit subnet associations" -> Select `cloudtwin-private-subnet-1` and `cloudtwin-private-subnet-2` -> Save.

4. STEP 2: VPC SECURITY GROUPS CONFIGURATION
================================================================================
Create 3 specialized Security Groups to enforce strict layered security.

Go to: VPC Console -> Left panel -> "Security groups" (under Security).

--------------------------------------------------------------------------------
2.1 Create ALB Security Group (Public Web Ingress)
--------------------------------------------------------------------------------
1. Click "Create security group".
2. Basic details:
   - Security group name: `cloudtwin-alb-sg`
   - Description: `Allow public internet ingress to ALB on ports 80 and 443`
   - VPC: Select `cloudtwin-vpc`
3. Inbound rules:
   - Click "Add rule":
     * Type: `HTTP` | Protocol: `TCP` | Port range: `80` | Source: `Anywhere-IPv4` (`0.0.0.0/0`)
   - Click "Add rule":
     * Type: `HTTPS` | Protocol: `TCP` | Port range: `443` | Source: `Anywhere-IPv4` (`0.0.0.0/0`)
4. Outbound rules: Leave default (All traffic to `0.0.0.0/0`).
5. Click "Create security group".
6. Copy the Security Group ID: `sg-0a1b2c3d...` (You will use this in the next group).

--------------------------------------------------------------------------------
2.2 Create App / Compute Security Group (EC2 & ECS)
--------------------------------------------------------------------------------
1. Click "Create security group".
2. Basic details:
   - Security group name: `cloudtwin-app-sg`
   - Description: `Allow compute ingress strictly from ALB on port 8000 and SSH`
   - VPC: Select `cloudtwin-vpc`
3. Inbound rules:
   - Click "Add rule":
     * Type: `Custom TCP` | Port range: `8000` | Source: Click the search box, select `cloudtwin-alb-sg`
   - Click "Add rule":
     * Type: `SSH` | Port range: `22` | Source: Select `My IP` (Protects your SSH access)
4. Outbound rules: Leave default (All traffic).
5. Click "Create security group".
6. Copy the Security Group ID: `sg-0e5f6g7h...`.

--------------------------------------------------------------------------------
2.3 Create Database Security Group (RDS PostgreSQL)
--------------------------------------------------------------------------------
1. Click "Create security group".
2. Basic details:
   - Security group name: `cloudtwin-db-sg`
   - Description: `Allow PostgreSQL access from app layer and local development IP`
   - VPC: Select `cloudtwin-vpc`
3. Inbound rules:
   - Click "Add rule":
     * Type: `PostgreSQL` | Port range: `5432` | Source: Click search box, select `cloudtwin-app-sg`
   - Click "Add rule" (For direct connections from your local machine to RDS):
     * Type: `PostgreSQL` | Port range: `5432` | Source: Select `My IP`
4. Click "Create security group".

5. STEP 3: AMAZON S3 STORAGE BUCKETS
================================================================================
CloudTwin requires two Amazon S3 buckets:
1. `cloudtwin-architecture-vault`: For architecture graph export JSONs, topology state, and node assets.
2. `cloudtwin-reports-vault`: For simulation run logs, CIS compliance PDFs, and cost breakdown exports.

S3 bucket names must be globally unique across all AWS accounts worldwide.
Choose a suffix such as your name or random digits (e.g., `cloudtwin-architecture-vault-santanu-101`).

--------------------------------------------------------------------------------
3.1 Bucket 1: Architecture Vault
--------------------------------------------------------------------------------
1. Search "S3" in the top console search bar and click on "S3".
2. Click the orange "Create bucket" button.
3. General configuration:
   - AWS Region: `Asia Pacific (Mumbai) ap-south-1`
   - Bucket name: `cloudtwin-architecture-vault-<your-name>-<random-digits>`
     *(Example: `cloudtwin-architecture-vault-santanu-8831`)*
4. Object Ownership:
   - Select `ACLs disabled (recommended)`.
5. Block Public Access settings:
   - Ensure `Block all public access` is CHECKED [x] (True).
6. Bucket Versioning:
   - Select `Enable` (Allows preserving and rolling back architecture versions).
7. Default encryption:
   - Encryption type: `Server-side encryption with Amazon S3 managed keys (SSE-S3)`
   - Bucket Key: `Enable`
8. Click the orange "Create bucket" button.
9. Copy the bucket name -> This is your `AWS_S3_BUCKET` in `.env`.

--------------------------------------------------------------------------------
3.2 Bucket 2: Reports & Audit Vault
--------------------------------------------------------------------------------
1. Click "Create bucket" again.
2. General configuration:
   - AWS Region: `ap-south-1`
   - Bucket name: `cloudtwin-reports-vault-<your-name>-<random-digits>`
     *(Example: `cloudtwin-reports-vault-santanu-8831`)*
3. Block Public Access:
   - Ensure `Block all public access` is CHECKED [x].
4. Default encryption:
   - Select `SSE-S3`.
5. Click "Create bucket".
6. Copy the bucket name -> This is your `AWS_S3_REPORTS_BUCKET` in `.env`.

7. STEP 5: AMAZON RDS POSTGRESQL DATABASE & SCHEMA MIGRATION
================================================================================
CloudTwin stores user accounts, projects, canonical architecture schemas,
and audit history in PostgreSQL.

--------------------------------------------------------------------------------
5.1 Create a DB Subnet Group (Required for VPC Placement)
--------------------------------------------------------------------------------
1. Search "RDS" in the top search bar and open RDS.
2. In the left panel, click "Subnet groups" -> Click "Create DB subnet group".
3. Subnet group details:
   - Name: `cloudtwin-db-subnet-group`
   - Description: `Private subnets in ap-south-1 for CloudTwin PostgreSQL`
   - VPC: Select `cloudtwin-vpc`
4. Add subnets:
   - Availability Zones: Select `ap-south-1a` and `ap-south-1b`.
   - Subnets: Check both private subnets (`10.0.128.0/20` and `10.0.144.0/20`).
5. Click the orange "Create" button.

--------------------------------------------------------------------------------
5.2 Create the PostgreSQL Database Instance
--------------------------------------------------------------------------------
1. In the left panel, click "Databases" -> Click the orange "Create database" button.
2. Choose creation method: Select `Standard create`.
3. Engine options:
   - Engine type: `PostgreSQL`
   - Engine Version: `PostgreSQL 16.3-R1` (or latest 16.x)
4. Templates:
   - For Production Twin: Select `Production` (Enables Multi-AZ).
   - For Minimal Cost / Learning: Select `Free tier` or `Dev/Test`.
5. Availability and durability:
   - Select `Multi-AZ DB instance` (Deploys standby in 2nd AZ for failover simulation).
   *(Or `Single DB instance` if using Free Tier)*.
6. Settings:
   - DB instance identifier: `cloudtwin-rds-postgres`
   - Master username: `cloudtwin_admin`
   - Credentials management: Select `Self managed`
   - Master password: Enter a strong password, e.g.: `Santanu2414`
   - Confirm master password: Re-enter the same password.
7. Instance configuration:
   - DB instance class: Select `Burstable classes (includes t classes)`
   - Choose: `db.t3.micro` (or `db.t3.medium`)
8. Storage:
   - Storage type: `General Purpose SSD (gp3)`
   - Allocated storage: `20` GiB
   - Storage autoscaling: UNCHECK "Enable storage autoscaling" (Prevents surprise bills).
9. Connectivity:
   - Compute resource: Select `Don't connect to an EC2 compute resource`.
   - Network type: `IPv4`.
   - Virtual private cloud (VPC): Select `cloudtwin-vpc`.
   - DB Subnet group: Select `cloudtwin-db-subnet-group`.
   - Public access: Select `Yes` (Allows connecting from your laptop development environment).
   - Existing VPC security groups: Remove `default` and select `cloudtwin-db-sg`.
   - Database port: `5432`.
10. Additional configuration (Click arrow to expand):
    - Initial database name: `cloudtwin`  <--- VERY IMPORTANT: Must be named `cloudtwin`
    - Backup retention period: `7 days`
    - Encryption: Check [x] "Enable encryption" (AWS KMS key `aws/rds`).
11. Scroll to the bottom and click "Create database".

--------------------------------------------------------------------------------
5.3 Retrieve Endpoint & Construct DATABASE_URL
--------------------------------------------------------------------------------
1. Database creation takes about 5–10 minutes.
2. Once the status shows "Available", click on `cloudtwin-rds-postgres`.
3. Under the "Connectivity & security" tab, find:
   - Endpoint: e.g. `cloudtwin-rds-postgres.c123456789.ap-south-1.rds.amazonaws.com`
   - Port: `5432`
4. Construct your `DATABASE_URL`:
   `postgresql://cloudtwin_admin:Santanu2414@cloudtwin-rds-postgres.c123456789.ap-south-1.rds.amazonaws.com:5432/cloudtwin`


--------------------------------------------------------------------------------
5.4 Apply SQL Schema to RDS
--------------------------------------------------------------------------------
Run the migration script included in this repository from your terminal:
```powershell
# Using psql (PostgreSQL client)
psql -h <YOUR-RDS-ENDPOINT> -p 5432 -U cloudtwin_admin -d cloudtwin -f database/aws_rds/001_rds_postgres_schema.sql
```
*(Or open pgAdmin / DBeaver, create a connection to the RDS endpoint, open `database/aws_rds/001_rds_postgres_schema.sql` and click Execute).*

       - Check `ap-south-1b` -> Select `cloudtwin-public-subnet-2`.
   - Security groups: Remove default, select `cloudtwin-alb-sg`.
   - Listeners and routing:
     * Protocol: `HTTP` | Port: `80`.
     * Default action: Forward to `cloudtwin-tg`.
   - Click "Create load balancer".
4. Click on `cloudtwin-alb`. Under the "Description" tab, copy the **DNS name**:
   *(Example: `cloudtwin-alb-123456789.ap-south-1.elb.amazonaws.com`)*.

   - Deployment configuration:
     * Family: `cloudtwin-backend-task`.
     * Service name: `cloudtwin-service`.
     * Desired tasks: `2`.
   - Networking:
     * VPC: `cloudtwin-vpc`.
     * Subnets: Select both private subnets.
     * Security group: Select `cloudtwin-app-sg`.
   - Load balancing:
     * Load balancer type: `Application Load Balancer`.
     * Select existing load balancer: `cloudtwin-alb`.

   - Click "Create".

9. STEP 7: SERVERLESS & EDGE DELIVERY (LAMBDA, API GATEWAY & CLOUDFRONT)
================================================================================

--------------------------------------------------------------------------------
7.1 Create AWS Lambda Function (`cloudtwin-order-processor`)
--------------------------------------------------------------------------------
1. Search "Lambda" in the search bar and open Lambda.
2. Click "Create function" (Author from scratch).
3. Basic information:
   - Function name: `cloudtwin-order-processor`
   - Runtime: `Python 3.11` (or Python 3.12)
   - Architecture: `x86_64`
4. Advanced settings (Click expand):
   - Check [x] "Enable VPC".
   - VPC: Select `cloudtwin-vpc`.
   - Subnets: Select both private subnets.
   - Security groups: Select `cloudtwin-app-sg`.
5. Click "Create function".
6. In the "Code" tab, double-click `lambda_function.py`, replace with this code:
```python
import json

def lambda_handler(event, context):
    return {
        "statusCode": 200,
        "headers": {"Content-Type": "application/json"},
        "body": json.dumps({
```
