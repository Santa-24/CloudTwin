2. STEP 0: IAM USER CREATION, POLICIES & PROGRAMMATIC ACCESS KEYS
================================================================================
The FastAPI backend uses the Python `boto3` SDK to upload architecture
snapshots to S3, record simulation events into DynamoDB, and query AWS health.

1. Search "IAM" in the AWS search bar and click on "IAM".
2. In the left panel, click "Users" -> Click "Create user".
3. Step 0.1: Details:
   - User name: `cloudtwin-admin-user`
   - Checkbox "Provide user access to the AWS Management Console": LEAVE UNCHECKED.
   - Click "Next".
4. Step 0.2: Permissions:
   - Select "Attach policies directly".
   - Search and attach:
     * `AmazonS3FullAccess`
     * `AmazonDynamoDBFullAccess`
     * `AmazonRDSFullAccess`
     * `CloudWatchReadOnlyAccess`
   - Click "Next" -> Click "Create user".
5. Step 0.3: Retrieve Access Keys:
   - Click on the newly created user `cloudtwin-admin-user`.
   - Click on the "Security credentials" tab -> Click "Create access key".
   - Select "Command Line Interface (CLI)" or "Application running outside AWS".
   - Check confirmation box -> Click "Next" -> Click "Create access key".
   - Copy `Access key ID` and `Secret access key` immediately to your notes.

3. STEP 1: AWS VPC & NETWORKING SETUP
================================================================================
CloudTwin models and deploys across a production VPC spanning 2 Availability Zones.

Using the Console Wizard ("VPC and more"):
1. Search "VPC" -> Click "Create VPC".
2. Select "VPC and more".
3. Configuration:
   - Name tag: `cloudtwin`
   - IPv4 CIDR block: `10.0.0.0/16`
   - Number of AZs: `2` (`ap-south-1a`, `ap-south-1b`)
   - Number of public subnets: `2` (`10.0.0.0/20`, `10.0.16.0/20`)
   - Number of private subnets: `2` (`10.0.128.0/20`, `10.0.144.0/20`)
   - NAT gateways: `In 1 AZ` (or None if running purely on public subnets to minimize costs)
   - DNS options: Enable DNS hostnames [x] & DNS resolution [x]
4. Click "Create VPC".

4. STEP 2: VPC SECURITY GROUPS CONFIGURATION
================================================================================
Go to: VPC Console -> "Security groups" (under Security).

1. ALB Security Group (`cloudtwin-alb-sg`):
   - VPC: `cloudtwin-vpc`
   - Inbound: Port 80 (HTTP) -> `0.0.0.0/0`, Port 443 (HTTPS) -> `0.0.0.0/0`.

2. App / EC2 Security Group (`cloudtwin-ec2-sg`):
   - VPC: `cloudtwin-vpc`
   - Inbound:
     * Port 22 (SSH) -> `My IP` (or `0.0.0.0/0`)
     * Port 80 (HTTP) -> `0.0.0.0/0`
     * Port 443 (HTTPS) -> `0.0.0.0/0`
     * Port 8000 (Custom TCP) -> `cloudtwin-alb-sg` (or `0.0.0.0/0`)

3. Database Security Group (`cloudtwin-db-sg`):
   - VPC: `cloudtwin-vpc`
   - Inbound:
     * Port 5432 (PostgreSQL) -> Source: `cloudtwin-ec2-sg`
     * Port 5432 (PostgreSQL) -> Source: `My IP` (Allows local laptop migrations)

   - VPC: `cloudtwin-vpc`, subnets: both private (or public) subnets in `ap-south-1a/b`.
2. Create Database:
   - Engine: PostgreSQL 16.x
   - Identifier: `cloudtwin-rds-postgres`
   - Master username: `cloudtwin_admin`
   - Master password: strong password (e.g., `Santanu2414`)
   - Instance class: `db.t3.micro`
   - Storage: 20 GiB gp3 (Disable autoscaling)
   - Public access: `Yes` (for setup convenience)
   - VPC Security Group: `cloudtwin-db-sg`
   - Initial database name: `cloudtwin` (Under Additional configuration)
3. Once Available, copy Endpoint and apply the schema:
   ```bash
   psql -h <RDS-ENDPOINT> -p 5432 -U cloudtwin_admin -d cloudtwin -f database/aws_rds/001_rds_postgres_schema.sql
   ```

13. STEP 11: REAL OBSTACLES FACED & ENGINEERING SOLUTIONS
================================================================================

This section documents the critical obstacles solved during testing and deployment:

13.1 Reload Reset Bug & State Persistence:
- **Obstacle:** Refreshing the browser (`F5`) in the dashboard or canvas redirected
  users back to the landing page, losing the active view.
- **Solution:** Initialized `inStudio` and `activeTab` from `localStorage`
  (`cloudtwin_in_studio`, `cloudtwin_active_tab`) and synced with URL hash (`#simulator`, `#cost`, etc.).
  The user remains anchored on their active tab across reloads.

13.2 Real-Time Auto-Sync Telemetry:
- **Obstacle:** Editing node configurations or adding components did not update
  cost calculations or security posture without manual saves or page refreshes.
- **Solution:** Added a 1.5-second debounced auto-save hook in `ArchitectureCanvas.tsx`
  with live toolbar indicators (`🟡 Auto-Syncing...` ➔ `🟢 Live Synced`), paired with
  centralized `syncTelemetry` in `page.tsx` that triggers parallel background re-audits.

13.3 Python Adapter Bugs:
- **Obstacle:** `/simulations/run` failed with 500 error due to `custom_params` NameError
  in `backend/integrations/simulation_engine/adapter.py`.
- **Solution:** Safely fetched `custom_params = scenario_config.get('custom_params', {})`.
- **Obstacle:** Recommendation engine failed accessing `b.resource_name`.
- **Solution:** Implemented attribute fallback checking `component_id` and `resource_id`.

13.4 Nginx Reverse Proxy 502 Bad Gateway Timeouts:
- **Obstacle:** Heavy Monte Carlo simulations took >60s, triggering Nginx 502 Bad Gateway.
- **Solution:** Extended proxy timeouts in `nginx.conf`:
  `proxy_connect_timeout 300s; proxy_send_timeout 300s; proxy_read_timeout 300s;`.

13.5 Insecure Blob Warnings & HTTPS Setup:
- **Obstacle:** Browser blocked insecure HTTP blob exports (`blob:http://...`).
- **Solution:** Configured free DuckDNS subdomain (`cloudtwin.duckdns.org`) with
  automated Let's Encrypt TLS 1.3 certificates via `infrastructure/deployment/setup-ssl.sh`.

13.6 Git Merge Conflicts on EC2:
- **Obstacle:** Direct file edits on EC2 prevented `git pull origin main`.
- **Solution:** Use `git stash && git pull origin main` for clean automated deployments.

14. STEP 12: SAFE TEARDOWN & AWS BILLING PREVENTION GUIDE
================================================================================

To ensure $0.00 surprise bills after demonstrations or testing:

1. EC2 Instance:
   - To Pause: `sudo shutdown -h now` or EC2 Console -> Instance state -> Stop.
   - To Delete: EC2 Console -> Select `CloudTwin-Production` -> **Terminate instance**.
2. Elastic IP:
   - EC2 Console -> Elastic IPs -> **Disassociate** and **Release Elastic IP address**.
   *(Crucial: AWS charges $0.005/hr for unattached/idle Elastic IPs!)*
3. RDS PostgreSQL:
   - RDS Console -> Select `cloudtwin-rds-postgres` -> Actions -> **Delete**.
   - Uncheck final snapshot, uncheck automated backups, type `delete me` -> Delete.
4. DynamoDB:
   - DynamoDB Console -> Select `CloudTwinSimulationEvents` -> **Delete** -> Type `confirm`.
5. S3 Buckets:
   - S3 Console -> Select each bucket -> **Empty** (type `permanently delete`) -> **Delete**.
6. Security Groups:
   - Delete `cloudtwin-ec2-sg` and `cloudtwin-db-sg` after instances are removed.
